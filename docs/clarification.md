# 结构化来源到有限澄清与后继任务

状态：2026-09-26 有限实现。requirements 首次成为公共任务链的消费者；只在调用方给定的有限解释与布尔行为问题内运行。工程验收不证明意图忠实性或元模型中心方法的比较优势。

## 当前闭环

应用在探索前固定父任务、初始模型、案例原字节和来源。案例列出至少两个解释、操作、证据需求、行为 probe 和预算；requirements 通过注入的预览与观察回调构造候选，并根据真实行为差异提问。脚本回答绑定问题规范哈希和原始回答制品引用。

确认回答在有限集合中留下一个解释后，应用使用预先固定的 probe→obligation 规则形成显式后继任务：保留父任务全部声明、义务、绑定、来源和基准，追加问题与回答对应的目标，同时改变任务与计划版本。派生记录保存父任务、案例、映射版本、回答及后继任务引用。后继任务经 `prepare_task` 固定后才生成正式 `ChangeProposal`，再进入已有 `run_task`。

探索候选发生在新增目标固定之前；正式提案发生在后继任务固定之后。这是可追溯的目标演化，不能将新版本结果冒充原任务版本的运行结果，也不能声称目标在所有候选产生前就已固定。派生目标的函数不读取获选候选，期望值直接取自有效回答，不从候选预测反推。

## 运行与文件归属

从仓库根执行：

```text
python -B apps/clarification.py --profile structural-graph
python -B apps/clarification.py --profile finite-automaton
python -B run_tests.py --package requirements
python -B run_tests.py --integration
```

| 位置 | 责任 |
|---|---|
| [requirements](../packages/requirements/src/modelspine_requirements/__init__.py) | 严格输入、来源检查、有限解释、观察绑定、问题选择、回答与提案；仅依赖 protocols/标准库 |
| [有限观察适配器](../adapters/clarification_checks.py) | 图可达与有限自动机固定输入串接受；从原 probe 和回答产生新义务 |
| [应用装配](../apps/clarification.py) | 显式文件读取、固定父任务、后继派生、证据记录、最终提案与提交链 |
| `domain-packs/{structural-graph,finite-automaton}/clarification/` | 公开工程案例、原始来源和脚本回答；不覆盖原 `tasks/` 合同 |
| [原任务提交入口](../apps/task_acceptance.py) | 后继固定目标验收和模型保存，沿用原语义 |

输出分别保留 session、derivation、successor、制品原文和任务运行结果。未决阶段没有后继任务或提交。获选解释不改变模型时为 `no_change`：仍构造并评估后继任务，返回原模型与明确的无提交结果。CLI 只有必需意图就绪且声明目标全部满足才返回 0；未决或目标未满足返回 1，输入/完整性错误返回 2。

## 提问与停止规则

候选是显式列表，不是对整个语言的穷尽搜索。每个 probe 对每个候选产生带绑定的 `observed/unknown/error` 观察。只有全部剩余解释都有确定布尔观察，且真假两组都非空时才能发出问题；选择能最大化较小分组大小的问题，同分按 ID 排序。该 minimax 规则不代表信息增益估计或校准概率。

候选预算超限不会截断列表后确认；观察预算不足保留已得结果并停止；每个已发出问题消耗问题预算。未知不当否定，无区分问题不当确认。显式待补证据、预算耗尽、拒答、冲突和剩余歧义均保持未决。过时问题、篡改内容、重复回答身份或缺失/错误来源明确失败，不回退到旧回答。

图问题只解释已验证的有限无环图上的固定端点可达性，包含零长度路径。自动机问题固定输入串，不以候选模型的 `trace` 替换它；受支持字符上的缺转移或非接受终态是正常 false，超出字母表为 unknown。坏图/坏机器不能变成一个有效的否定回答。结构与义务适用范围沿用[公共基础边界](foundation-boundaries.md)。

## 信任与版本

案例、来源和回答按原始 UTF-8 字节核对 SHA-256，记录身份与版本；问题哈希覆盖父任务、模型基准、案例、剩余解释、probe 和行为见证。来源采用显式引用→字节映射及行位置。应用在后继边界重新核对实际使用的案例与回答对象是否对应原字节，并重新准备父任务；不只核对旁边附带的一份来源哈希。

新任务版本必须不同于父任务版本和父计划版本；原任务不被原地编辑，父义务不会被删除或削弱。最终提案即使符合新回答，也必须通过所有保留的父义务。核验通过仍不证明自然语言与规则的语义一致，脚本 actor 也不构成真实用户身份认证。

`Session` 和 `PreparedTask` 是可信进程内值，回调由应用显式装配；这里不实现任意会话反序列化授权、永久版本注册表或持久化事务。评价 oracle 不进入问题选择、目标构造或提交路径。测试侧发现开发观察与检查共同错误时，必须分别记录开发结果与独立评价失败。

## 实现边界与验收入口

工程验收围绕真实区分问题、两个有限语义族、连续过滤、预算停止、unknown/error、来源与问题篡改、拒答/冲突、no_change、父目标保留及下游拒绝组织。测试命令和最终结果由[平台验收记录](validation.md)统一维护，不把源码存在或输入哈希通过当作行为验收完成。

本轮没有自动 `mapping_error/model_gap/representation_gap` 分类、全语言不可表达证明、自然语言候选抽取、支持/反对证据推理、Jev/LLM、元模型迁移、Studio UI 或正式比较研究。下一工作应依据本轮残余与独立评价推进；不能从单个结构化切片直接推导 P1 已完成或比较优势成立。
