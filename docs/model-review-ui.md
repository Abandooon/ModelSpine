# 本地候选审阅 UI

本入口离线读取本地审阅项目，展示原文、术语/字段、关系、规则、问题、残余、诊断、实例和用户记录；可以保存/检查实例、明确采纳合法提案、下载回答修订材料，以及编辑和确认应用配置。不要求生成应用代码，不调用模型或外部API。旧审阅会话可直接打开。

2026-10-03 扩展只消费 A 的新审阅合同：可显示时间、导航、过滤、计数和操作资格作用域，记录外加澄清，登记已有回答修订产物并另行明确采纳。新版本定义目前不能使用旧版应用配置。工程验证与同一真实项目的 F2 验收仍须区分。

从 `platform/` 启动（Python 3.10+，标准库，无 npm/Web 框架安装）：

```text
python -B -I apps/model_review_ui.py --project-dir "E:/absolute/existing-review-project"
```

浏览器打开终端输出的 `http://127.0.0.1:随机端口`。可用 `--port 8765` 指定本机端口、`--actor "用户归属名称"` 标记操作者；该名称不是登录认证。Ctrl+C 停止。服务只接受启动时指定的一个绝对目录，页面不能选择其他磁盘目录。

已有目录必须由 [A 的审阅入口](model-review.md) 保存过会话。首次创建可在显式已存在空目录上直接装配 A 接口：

```text
python -B -I apps/model_review_ui.py --project-dir "E:/absolute/empty-project" --request "request.json" --candidate "candidate.raw" --session-id "review-1"
```

三项创建参数须齐全；已有会话拒绝覆盖。request 必须是 A 的 ModelingRequest，candidate 是外部原始响应字节，非法候选也可审阅。此入口不调用语言模型、不自动生成示例作为缺失真实输入的替代。

页面先显示简要版本和独立状态；术语/字段表标明类型与必填/可空，关系显示端点名称及双向基数，规则分别展示上下文、适用、断言、例外。表达式只格式化、不求值；AND/OR 组合保留括号。完整 JSON、来源、精确引用及原件在详情中。非法原件保持可见并展示诊断。精确显示使用服务器 presentation 字符串和原件，前端不得从已解析 view 的 JS Number 重建表达式、详情或候选，以免 Int64 舍入。

可答复/拒答、勾选明确目标确认、提交完整 UTF-8 候选文本及修改理由。`review:candidate` 的整体确认与 `$candidate` 元素确认分开列出。意见/提案仅收到持久化回执才显示“已记录”，不因此显示候选已修订/已接受。保存后从页首链接在新窗口读取最新记录继续，旧页及未提交输入保留；旧页再次提交会产生明确版本冲突，不自动换版本重发。取消清空本表单，不提交；布局切换不写语义。草稿只保存在当前页面，保存过的记录才可重开恢复。

实例操作：在“保存实例”选择示例、反例或项目用途，输入完整 ProjectModel JSON，definition须等于页面所示定义引用。可显式填入空结构模板后编辑；模板不含生成实例。JSON原文本送严格解码，Int64不经过浏览器Number重建。保存后重开，实例/字段/关系表保留用途与版本绑定；点击“执行检查”取得本次只读结果。检查不写报告缓存，unknown/error/违反/不适用均保留，反例用途不把违反改成通过；必要残余仍可令结果未决。

采纳操作：合法完整提案保存后重开，复核提案原件及来源，在“明确采纳提案”填写理由并勾选明确采纳。收到真实回执后显示前后候选版本，打开后继链接；这不等于需求语义通过。版本选择器可只读查看旧原件、回答、未决、实例和采纳记录，返回当前页仍保留草稿。新候选不继承旧确认或实例结果，旧实例不能当新版本检查；非法提案不能采纳，非法候选仍展示原件/诊断。

本UI不执行回答驱动的语言调用或应用生成。遇 busy、incomplete_write、IO 或版本错误，先保留输入和错误再从新窗口核验；不自动删锁/pending 或回滚。能力串、Host/Origin 校验仅减少本地误写和恶意网页写入，不是完整认证或多租户保护。

## 时间、操作资格及外加澄清

定义版本按 A 核验结果分派，`finite-domain/0.1` 保留原字段/关系计数语法，`finite-domain/0.2` 显示 `self/var/get/navigate/filter/count` 与 `instant/duration/add/sub`。例如 `count(filter(navigate(self, "samples:out"), "sample" => ...))` 明确显示集合导航方向、绑定变量与过滤谓词。UI只格式化、不计算、不消除括号或简化逻辑；duration明确标秒，UTC整秒字符串不转本地时区，Int64由服务器文本保存精度。未知版本/算子明确不支持，原件和诊断仍可审阅。

规则表区分“库存完整性 invariant”和“操作资格 eligibility”，资格规则另列operation。实例保存后可分别检查库存完整性，或在资格表单明确选择operation和目标对象再检查。资格入口仅调用 A 的已保存实例引用函数，不从浏览器组装一个临时实例直接求值。显示 `action_execution=not_run`：没有执行提交、权限变更、生命周期或历史保留。即使某条资格满足，其他unknown/error/必要残余仍保留；没有整体通过结论。取消与布局/历史切换不写入。

“记录外加问题、更正与回答”创建独立问题记录，与候选原问题区分。分别填入问题原话与归属、更正原话与归属、回答/拒答原话、单独解释与解释归属；回答actor取服务启动标记。归属只是标记，不是认证。不要将总领解释复制成用户原话：例如用户“采用以上补充需求”与总领整理的字段清单应各放在response_text与interpretation_text。原始source不覆盖，回答也不表示候选被确认。保存后新窗口读取，可看到每部分及其实际动作/问题引用。

“登记已有回答修订产物”只接收已有产物及 A 的完整绑定材料，不含付费/API按钮，也不接受服务器文件路径。表单JSON必须且仅含五项：实际action_refs、revision_ref、response_ref、原始响应字节的proposal_base64、生成时冻结的方法完整原文method_instructions。方法原文缺失时停止，不能从当前代码补值或把后来的提示冒作历史。父请求/候选/review由本页所见身份封装，旧窗口会冲突而不丢稿。登记只增加审阅记录，当前候选仍不变；非法原件也展示诊断，但不能采纳。用户须重开、复核，再填写理由并勾选明确采纳。采纳后可查看原始候选、原问题、外加问答及各自解释来源；新候选不继承旧确认或实例结果。

修订候选的来源表分开显示 source 的原文行号/引用和 action 的问题、动作、question/correction/answer/decline部分。解释不是可冒用的用户证据，实际绑定拒绝归 A。生成来源 `not_verified` 不表示认证过的语言调用来源。普通改提示后的历史重放与冻结方法身份也归 A；UI不复制重放或修复旧记录。

当前LocalWebSpec及生成消费者仅支持旧版有限定义；新版本候选的应用配置模板、读取、准备、确认和保存入口明确拒绝，不显示旧表单冒充支持。普通答复/拒答仍可使用原离线下载；外加澄清的新版执行修订材料由 A 独立入口准备，本UI未装配其下载接口，会明确提示。

## 离线修订材料与应用配置

在“导出回答修订材料”勾选实际保存的答复/拒答，点击下载。浏览器收到 A 公开函数返回的完整 [revision-context/0.1](revision-request.md) envelope；保留问题、原话、历史候选来源、原候选字节及审阅绑定。状态仍为待调用/not_run，没有伪造 ModelingRequest 或新候选。服务只用自行创建的临时目录导出并清理，HTTP 不接收输出路径。旧页导出也校验 review head，冲突时保留勾选。

“准备应用配置”是 [LocalWebSpec](application-spec.md) 的完整 JSON 编辑器。页面展开“字段结构与填写方法”可查看所有配置项和嵌套字段；“可引用的原文及实际用户记录”提供真实来源、动作与实例引用。结构模板不替你决定初始数据、编辑范围、权限或保存配置。id 是稳定应用标识；version 每次更改保存须使用未用过的新值。

1. 填完整 JSON 并“保存当前草稿”。保存允许存在就绪阻碍，页面逐项列出 A 实际检查结果。
2. 在版本号框填写下一版本，点击“准备确切配置”。该按钮只按你的选择更新 version，并用 A 的 acceptance_digest 计算公开样例内容摘要；不会产生样例或检查预期。检查预期须从实际实例报告按完整顺序填写 obligation/target/status，不能省略不利结果。公开 case.ref 可先用64个0占位，准备后生成真实摘要；artifact_id/revision 仍须由用户明确填写。
3. 阅读展开的完整配置，勾选主动同意后“明确确认这份配置”。编辑内容或版本号会取消本次准备和勾选。UI 使用 A 的内容 hash 约定记录专用确认；普通候选确认不授予应用许可。确认只表示意见已记录，尚未保存应用配置。
4. 点击“保存当前草稿”，再用页首链接新窗口读取。只有 A 的重新检查无阻碍才显示配置就绪；这不表示应用已经生成或验收。改动内容后从步骤2继续。旧候选/审阅/配置提交409或保持绑定阻碍，不自动换版重发。

确认循环不要求手输 hash。准备的 hash 包含版本和全部配置，仅排除 review_ref / confirmation_refs；专用确认回执只更新这两个字段，然后显式保存。已保存旧版本不能原地改写：例如先保存1，准备2并确认，再保存2。确认和保存是两次独立操作，中间并发变化会使保存失败，已记录确认仍留痕，草稿保留待核对。

完整 spec 通过服务器 `spec_text` 字符串载入/准备/确认/保存/重读；提交直接嵌入原 JSON 文本。下载使用 `envelope_text` 字符串，不能把解析后的 JavaScript Number 重新序列化为完整 spec/envelope。Python 严格解码后可以重排 JSON，但 Int64 数值不变。当前 HTTP 上限仍为512 KiB（包括载荷包装），比共享 spec 上限更窄，超限明确拒绝。

无需安装新依赖。应用使用已注册的 `bootstrap.activate(("interaction",))`；本包不修改 bootstrap。页面历史导航继续只读，切换布局/候选不保存配置。配置读失败不以空草稿替代，未提交草稿只在页面内存中。
