# 单一候选后端接入合同

状态：**宿主载荷与重放子集已实现；真实后端仍未接入**，2026-09-27。供应商、模型、端点、认证环境变量与实际调用预算尚待确定，没有调用外部API，也没有真实后端结果。下文明确区分当前宿主接口与后续传输/收据设计；当前代码仍以[有界构造](bounded-construction.md)及源码为准。

## 目标与真实干预

让一个真实候选后端读取已固定的任务、模型和允许编辑空间，**一次返回有限、有序的选项提议**，再经过既有构造控制、完整终验与真实模型保存。第一版检验“后端提议的选项能否经过受控构造成为合格模型变化”，支持范围仍是合法扁平 DAG 的单边端点重定向。它不是任意代码生成、一般图生成或交互式修复代理。

后端输出选择意图；可信宿主把合法选项 ID 映射为现有 `EditOption`，调用现有 builder 产生 `ChangeProposal`。后端不能自报已通过、提交模型、更换目标、扩大允许空间或提交任意 Python/工具调用。选择有限选项也是实际后端工作，但不应称为开放生成能力。

实际顺序是：固定输入与预算 → 后端生成完整响应 → 解析与成员核对 → DAG/普通规则控制 → 提案构造 → kernel.preview → 全义务终验 → 固定任务接纳与模型保存。DAG 控制发生在 **LLM 响应之后、模型提案构造之前**。它没有约束模型的 token 生成，不得称“LLM 生成前硬约束”。提示中的规则仅提供信息；供应商 JSON 格式约束即使可用，也只说明输出格式支持，不证明无环或任务正确。

独立参考只在方法结束后由评价者运行；其规格、答案、错误提示与结果不进入后端输入，也不驱动补发请求、重排选项或改目标。开发检查结果在第一版同样不反馈后端；这里没有修复循环。

## 当前边界与最小挂接

现有 `modelspine_generation.bounded.search` 只接受完整的 `tuple[EditOption, ...]`，会先验证元组，再依次 control/build/evaluate。它没有异步输入、流式候选、工具消息或 API 预算。原 `run_construction` 继续传入 `prepare_dag(...).options` 的完整固定顺序；新宿主入口可把经过绑定验证的有序选项子集送入同一执行步骤，允许按响应顺序重排。

接入分为以下三个有限变化，当前仅完成第2项及其载荷边界：

1. 单一外部后端适配器执行一次请求，返回响应和执行收据。适配器只依赖需要的公共值对象；不导入 apps、studies、测试或参考评价，不建立多后端注册／自动路由框架。
2. apps 已将输入验证／constructor 准备与“对选定 options 执行 search 并接纳”分为共享的内部步骤。原 `run_construction` 继续使用完整固定元组；`candidate_batch.run_candidate_selection` 核对绑定，再将从当前完整目录映射的原选项对象送到同一执行步骤。每次执行从固定base新建kernel；原 API、`BoundedTaskRun` 与 deterministic 条件保持语义。
3. 新增 apps 层后端结果信封，分别保存 `backend` 收据、`selection` 及可为空的 `app_result: BoundedTaskRun`。失败发生在后端／解析阶段时 `app_result=null`，不能制造一个未运行的 `ConstructionRun`。宿主执行异常另记 `execution_error`；若没有返回保存收据，保存状态保持未知，不能推断回滚。

当前 [candidate_batch.py](../apps/candidate_batch.py) 提供 `prepare_candidate_request(inputs, source_contents, *, request_id, limits)`、`parse_candidate_selection(request, response_bytes)`、`run_candidate_selection(inputs, request, selection, *, controller=None, construction_plan=None)`。`CandidateLimits` 只管理物化前目录规模及提议条数、请求正文和响应载荷的UTF-8字节上限。来源仍按原字节哈希核对，提取已声明行定位；请求包含完整任务/模型/元模型/空间及无答案标签的选项目录。选择记录包含原响应文本/哈希、完整请求哈希及按序选项ID/哈希；重放重新核对实际输入、规则与完整目录。`CandidateBatchRun` 只记录该批次的真实宿主执行及`backend_batch`范围，不代表后端收据或API已经发生。值对象是可信本机装配，不是可移交的授权凭据。

其中 `backend.status` 为 not_started/returned/timeout/error，error 另带 transport_error/service_error 等实际错误类型；`selection.status` 为 not_run/valid/response_invalid。例如 HTTP 调用正常返回但 JSON 非法，必须同时记录 backend=returned、selection=response_invalid。`app_started` 显式区分“尚未调用”和“调用后未返回”；真实返回的搜索和保存字段保留在 app_result 中，不合并为一个 success。

完整后端的设计入口仍为 `run_backend_construction(fixed_inputs, backend_config, *, controller=None, construction_plan=None)`；此签名尚不是可调用 API。已实现的宿主准备／执行步骤供研究侧重放已记录的选项提议。研究条件选择与跨条件重放归 studies；不向运行包增加 condition 枚举。generation.search 及其 DTO 不变，protocols 未增加供应商字段。

若未来需要根据终验反馈逐次请求新候选，必须另定预算、重复候选、反馈权限和跨请求状态合同；不能在本次接入中暗加循环，也不能把每次重新调用现有 search 的局部预算冒充总预算。

## 固定输入与输出

每次请求在调用前完成下列绑定。输入来源可使用公开工程任务；未来非公开数据须另确认允许发送范围，凭据不属于任务数据或运行证据。

| 输入 | 固定内容与责任 |
|---|---|
| request 身份 | 宿主生成唯一 request_id；绑定 task_ref、base、space_ref、check_plan_hash、候选目录哈希及后端配置／提示版本 |
| 任务与模型 | PreparedTask 对应的已确认来源片段、完整目标／义务、元模型、当前 Snapshot；明确保留目标、允许修改及未覆盖范围；不提供参考规格 |
| 候选目录 | 当前 prepare_dag 的全部 EditOption，含 id、target、source/target 值，保持固定目录顺序；不带 allow/exclude、终验或正确答案标签 |
| 提议上限 | max_returned_options；max_considered_options 是固定 DagEditSpace.max_options 的记录名称，不新增另一个可独立修改的控制预算；返回列表可以短于上限或为空，不保证覆盖全部解 |
| 执行限制 | 单次请求上限、请求超时、最大输出 token、允许的输入／总 token 或费用上限及核算方法；不能只写 max_options |
| 后端配置 | 一个显式端点／模型标识、可固定的模型修订、采样参数和可用的 seed 设置；不允许失败后改模型或参数 |

请求目录中的选项尚未经过 DAG 控制；三种前控条件看到同一目录和任务信息。允许后端阅读完整开发义务，不能向某一组免费提供其他组需要推导的规则或答案。若完整目录超过声明的输入或准备资源范围，调用前显式停止为 unsupported/resource_limit，不截断目录、丢义务或悄悄换检索策略。宿主在物化前按固定空间的边／源／目标数量核对预定目录规模上限，不能用控制预算限制准备成本；空目录直接保留无选项结果，不花一次 API 调用让后端返回空列表。

响应的候选载荷只接受以下 JSON 形状；示例 ID 来自固定目录，不表示推荐答案：

```json
{
  "schema_version": "candidate-selection/0.1",
  "request_id": "construction-request-001",
  "option_ids": ["structural-graph-edge-space/option-1", "structural-graph-edge-space/option-2"]
}
```

严格解析完整候选载荷，拒绝附加字段、重复键、错误类型、错误 request_id、重复选项、超长列表和目录外 ID。第一版不从散文或 Markdown 中猜 JSON，不删去坏项后把剩余部分当成功，不补默认候选。供应商响应外壳及其内容提取规则由所选适配器版本固定；候选载荷之外的供应商元数据保存于收据，不交给 search。

宿主按原顺序将每个 ID 解析为目录中的原 `EditOption`；不采信后端提供的字段值或 proposal/base/hash。规范化选择记录至少含 request_id、task_ref/base/space_ref、目录哈希、按序选项 ID／哈希及原始响应哈希。跨任务或新模型 revision 重放必须因绑定不符被拒绝；相同绑定下的研究重放可复用同一响应。

选项目录完整性校验不等于领域约束判断。例如自环选项可以属于合法的端点空间：仅终验组会构造后拒绝，DAG／普通规则组在提案构造前拒绝。将自环误当“响应解析错误”会抹掉研究干预。

空列表是合法的“无提议”，后端状态为 returned，search 对空元组返回 exhausted，没有新提交。结果必须标记 `exhaustion_scope=backend_batch`，并保留完整目录大小与提议大小；不得据此声称完整允许空间无解。非空提议批次全部用完时也适用这一限定。现有 search 的 `option_space_exhausted` 原原因保留，外层说明这里传入的是后端批次。

## 预算、失败与停止

第一版每个固定任务阶段至多 **一次**真实后端请求，无自动重试、反馈修复、模型切换或缓存替代。多个任务阶段分别计请求，并受事先固定的整条轨迹预算限制；不能因为前一阶段失败而重置轨迹账本。以下计数不互相替代：

| 计量 | 语义 |
|---|---|
| backend_attempts | 已尝试发起的传输次数；超时或错误仍计入。到达调用前的输入拒绝为 0 |
| API/token 用量 | 供应商返回的输入、输出及其他计费用量逐项保存；无法取得为 null+原因；不能从候选数推算 |
| returned_options | 严格解析后的提议数；载荷非法时为 null，原始响应仍保留 |
| considered_options | 实际 control 调用次数，含 exclude/no_change；继续沿用 search 的 max_options 语义 |
| 构造与检查 | 构造次数、搜索终验及最终接纳检查分别统计，不能把省一个候选等同省一次 API 调用 |
| 时间与费用 | 后端等待、宿主计算、独立参考及落盘分开；实付／供应商账单、按固定费率计算的估计与未知分别标识 |

硬预算须可执行。调用前结合完整输入、供应商计量方式与最大输出额度判断是否可发起；若无法保证声明的 token／货币硬上限，则本配置不具备该预算能力，不能把未经保证的估计称为硬上限。支持的请求超时约束宿主等待；超时后服务端是否继续计算或计费可能未知，收据明确记录。后端选择时须确认这些能力，不能提前假定所有供应商支持 token 上限、固定修订或 seed。

| 事件 | 必须记录的终止行为 |
|---|---|
| 调用前输入、绑定或预算不合法 | 不请求后端，不执行 search；保留拒绝依据及 planned/started 状态 |
| 后端 timeout／transport_error／服务拒绝 | 收据保留可获得的请求 ID、原始错误、耗时与用量；停止，不重试，app_result=null |
| 返回截断、无候选载荷或解析／成员验证失败 | response_invalid，保留完整原始响应及具体失败；停止，无部分候选执行 |
| 合法空批次或只有 no_change／被排除项 | 完成实际 search，保留 exhausted 与 backend_batch 范围；无保存不能改写为后端错误 |
| option 预算耗尽 | budget_exhausted，保留已处理步骤和尚未处理的提议数量；不再请求后端 |
| control／终验 unknown 或 error | 沿用现有 search 停止语义；不降低检查强度，异常记录后传播 |
| 搜索找到满足候选 | 仍经既有固定任务接纳；保存只由真实 commit 证明，不能由搜索／后端返回成功字符串代替 |
| 独立参考失败或执行异常 | 与实际保存分别记录，沿用现有 study 失败记录责任；不反馈方法、不重新调用后端 |

应用成功返回、模型已保存、独立参考满足是不同字段。外部调用中断但是否已计费不明时，不能记零费用；模型接纳异常但没有返回完整事实时，不能记 saved=false。采集采用现有 study 的检查点责任，后续错误不得抹去已完成调用、原始响应或保存收据。

## 两个消费者与可验证用例

**消费者 1：apps 的一次真实候选提议与模型保存。** 固定当前 DAG 任务及九选项目录，预置 backend_attempts≤1、max_returned_options=3、max_considered_options=2。若一次合格响应依序提议 a→a、a→b、a→c，DAG 前控排除第一项，第二项经构造／终验后失败；两次 control 已用完，第三项不执行，结果 budget_exhausted 且无保存。API 调用是 1，不是 2 或 3；选项前控没有减少已发生的 token 费用。预算在调用前改为 3 的独立计划运行才能考虑第三项并走真实保存，不得在本次结果后补预算。实现时可先用固定收据做工程验收，但该测试不计为真实后端运行。

**消费者 2：studies 的同批后端提议三条件重放。** 评价者先固定任务和参考，真实后端在公共、无条件标签的输入上调用一次；将绑定的相同有序批次交给 terminal-only、DAG 前控、独立普通规则前控。三组保留相同构造器、终验、保存条件和 max_considered_options。上例预算预定为 3 时，三组均可到达 a→c，前控组少构造一次自环提案。这隔离“对既定后端提议的前控效果”，不能当三次独立 LLM 生成、条件特有提示效果或生成成功率比较。

共享响应的三个记录引用同一个 backend receipt；实际调用和费用在合并分母中只计一次，不能重复记三次，也不能称某组免费获得候选。若另报告每条件独立执行的估算费用，必须显式标为估算，不能和真实总费用相加。将来如比较各条件独立在线生成，须另固定提示干预、随机化／重复及真实调用预算，不能把此重放改名为该实验。

两个消费者共用同一严格解析／绑定和宿主执行路径。宿主工程验收覆盖跨任务重放拒绝、严格载荷校验、空批次范围及完整终验/保存。真实传输尚未接入，因此“目录外ID返回时已有API成本”“超时未重试”等传输验收仍待实现，不能由固定响应测试冒充。

## 证据与公平比较

每次运行记录固定的模型／端点标识、模型修订或其不可固定原因、适配器／SDK／提示及响应 schema 版本、完整候选目录身份、请求参数与原始候选响应。保留供应商 request/response ID、结束原因、可用 usage 和费率／账单依据；seed 分别记录 requested、供应商支持／确认及实际可见值，不存在时为 null+原因。相同 seed 不自动承诺后端确定性。

原始请求证据保留实际发送的消息体和参数，不包括认证头、密钥、本机凭据或非必要账户信息。响应保留外部服务实际返回的可用内容与元数据，不要求不可获取的内部推理。公开工程数据的原始响应可以按版本与哈希登记；含非公开数据时保存在授权位置，公开记录仅引用可公开的身份与说明，不能为了复现把私人材料提交到公开仓库。

普通程序对照独立实现相同规则，并允许正常的参数化与复用；共享规则内容、触发时点和预算。固定选项下的判定差异可能来自控制算法，不能归因为“元模型组织”。现有 DAG 控制是显式适配器语义，并非通用元模型编译结果。解析器、后端失败路径和完整终验对所有条件一致，不能向某组增加重试、隐藏失败或更宽松的目标。

保留 planned、started、returned、有效批次、实际 app 返回、保存、参考结果及所有错误的完整分母。候选、选项、同一批次的三条件和同一轨迹阶段均具有相关性，不能直接当独立统计样本。人工作业时间和初次适配成本从实际实施开始采集；未测成本维持 null，不用零或代码行数代替。

## 下一实现前必须固定的配置

必须选定一个真实后端及其可固定版本、端点／认证获取方式、确切请求与响应提取方式、token／费用／超时能力、提示全文和采样参数。再固定本轮任务集、一次请求的选项上限、每阶段和整条轨迹预算、实际输入资源上限、原始响应保存位置与发布范围。缺少这些配置仍为未就绪，不能开始付费实验或报告真实后端结果。

不要求此时新增通用元模型编译器、流式搜索、多后端兼容层、工具调用循环、NL→合同生成或 Studio UI。完整接入完成的判据仍是上述两个消费者通过真实边界与失败验收，并至少保留一次实际后端请求到候选执行的可核验收据。当前只完成不依赖供应商的宿主子集，模拟响应验收不能代替该出口；generation 的 implemented-slice 与研究假设状态不升级。
