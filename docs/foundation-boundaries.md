# 公共基础支持边界

公共基础用结构图和有限自动机两类非业务配置检查同一公共合同。它们是有限语言的工程样例，不指定应用试点，也不证明任意领域可表达或元模型中心方法优于其他方法。既有验收结果见 [validation.md](validation.md)；本轮任务边界已完成有限实现与 126 项工程验收。

## 已实现与明确未支持的范围

| 层 | 实际责任 | 边界 |
|---|---|---|
| protocols | 严格 JSON、元模型身份/内容、元素 ID、整数/字符串/布尔字段、来源引用格式；本轮新增独立任务信封及公共报告校验 | 无原生关系类型、集合、单位、浮点、跨模型引用解析；来源引用合法不等于来源真实 |
| model-kernel | 单实例内存快照、六类变更、检查绑定、决定/提交和证据适用性 | 不负责解释图或状态语义；无文件/应用数据事务、通用迁移；同实例历史内删除的 ID 不再复用 |
| assurance | integer_range/equals 设计字段检查；纯内存任务准备与固定计划评估 | 缺目标 error；目标存在但规则未支持 unknown；不解释任意自然语言或授予应用许可 |
| generation | 单字段控制、有界选项搜索与记录、纯修复报告比较；DAG 语义通过适配器供给 | 单边端点重定向可前置排除回路；所有义务仍终验，无一般图/行为生成器或 LLM |
| 结构图适配器 | 局部字符串端点的存在/类型、有限有向图无环 | 仅根的扁平直接成员，嵌套成员明确拒绝；不是原生引用系统或任意图约束求解器 |
| 有限自动机适配器 | 端点、确定性、有限输入串执行和接受状态；符号是单个 Unicode 码点 | 仅扁平成员；不含层次/并发状态、guard、数据效果、epsilon 或时序逻辑；不是应用运行时 |

元模型版本/哈希错配、非法基础形状以及陈旧模型基准明确拒绝。无迁移入口时不能把换元模型当普通字段编辑。某种规则无法判定时保留 unknown；已知本地语义错误为 violated；缺少目标或配置合同错误为 error。未支持的任意字段类型由严格协议拒绝，不能默认转字符串继续。

`Obligation.field` 在 v0.1 必填，适配规则将它用于主要语义定位；它不是完整读集。真正无字段的模型级义务、原生引用/集合及迁移，仍需在出现实际消费者后评审接口。字符串端点含义由适配器确定，内核不会猜测字段名代表引用。

## 集合依赖与证据

内核按声明依赖计算已有元素指纹，不能自动跟踪集合成员资格或将来新增成员。仅枚举当前全部节点不足以证明全图依赖完备。因此两配置的 Graph/Machine 根必须列出当前实际成员依赖并设置 `dependencies_complete=False`；适配器拒绝错误的 complete 声明。

检查结果 satisfied 表示本次快照满足所检查的有限规则。证据适用性 unknown 表示不能证明旧报告可复用，两者可以同时成立；已有依赖改变时旧证据为 stale。不能因原报告为 satisfied 就跨修订自动复用。局部字段检查的完整无关依赖仍可保持 current，原有验收继续覆盖这一行为。

安全的全图 current 需要集合锚点和原子成员维护，或可核查的读集追踪；本轮没有实现这些机制，也没有为了得到 current 而弱化检查范围。

## 文件归属与实际调用

- [结构图配置](../domain-packs/structural-graph/README.md)、[有限自动机配置](../domain-packs/finite-automaton/README.md)拥有各自有限语义、元模型、模型及义务。
- [finite_models.py](../adapters/finite_models.py)实现两个 Checker，只依赖 protocols 与标准库。包内不出现 profile 分支或论文条件。
- [fixtures.py](../apps/fixtures.py)按显式目录加载三份 JSON；缺文件、非法数据直接失败，不选择后备配置或检查器。
- [boundary_examples.py](../apps/boundary_examples.py)显式装配配置、检查器和内核，执行 load → preview → check → decide → apply。状态机模型的修改仍是设计修订，不把模拟执行的每一步当模型提交。
- [test_foundation_boundaries.py](../tests/test_foundation_boundaries.py)验收两类语义的正反行为、残余和错误不提交；生产包与适配器的依赖边界单独检查。

研究方法可在 studies/适配器层替换 Checker，但必须满足候选、计划、范围、前提及义务绑定；工具实现不同不自动意味着独立真值。公共协议的结构完整性、规则解释正确性、意图忠实和比较效果仍是不同的证据责任。

既有 boundary_examples 自动机样例中的 trace 是可编辑模型数据，该 CLI 同时编辑转移符号和输入串，只展示重新执行和提交。它不是固定的独立验收输入；负例另验证只改转移时原输入串确实被拒绝。下面的新任务入口另外固定输入，不改变旧样例的含义。

## 本轮新增任务边界

任务材料和候选模型分别版本化。TaskContract/TaskAssessment 由 protocols 定义，PreparedTask 与评估由 assurance 拥有，apps 读取文件并装配提交流程。详细接口与错误语义见[任务合同](../packages/assurance/contracts/v0.1/tasks.md)，验收范围见[本轮交接](next-iteration.md)。

| 新增责任 | 当前实现范围 | 不能据此推断 |
|---|---|---|
| 任务准备 | 核对预先指定的任务/来源原始字节 SHA-256、任务身份/基准、UTF-8 行定位以及声明—义务映射 | 哈希一致不证明来源真实、映射忠实或作者有外部授权 |
| 意图就绪 | 必需声明须为 confirmed intent、有来源、无待补原因且有明确映射；合法未覆盖或无计划保留 unresolved | 不能将已确认 fact/hypothesis 自动升级为用户目标；可选声明未决不自动阻止全部任务 |
| 固定开发目标 | `graph_reachability` 检查固定节点可达性；`trace_acceptance` 使用计划参数中的固定输入和布尔期望 | 无效图/机器不能作为负向期望成功；输入超出有限字母表为 unknown；没有一般图/行为求解器 |
| 评估与保存 | 逐义务报告和意图状态分别保留；只有意图 ready 且全部开发义务 satisfied 时，apps 才调用 kernel 决定/提交 | TaskAssessment 不包含提交事实；模型保存不代表独立评价通过或应用交付 |
| 参考验收 | 测试侧另行固定规格和输入，以独立遍历/状态展开实现检查终候选 | 工程材料公开、作者可能共同，未形成盲测研究真值或独立专家证据 |

引用完整性错误直接拒绝；合法但尚无可执行计划的任务返回 candidate/report=None、goal_status=not_checked，不预览候选也不创建空计划。存在部分已知义务时仍执行并保留结果；未覆盖的必需目标继续未决。Checker 报告必须覆盖调用方事先选定的完整计划范围，不能用其自报的局部范围伪造满足。

[task_checks.py](../adapters/task_checks.py)和[task_acceptance.py](../apps/task_acceptance.py)是开发检查与应用装配入口；[task_oracle.py](../tests/support/task_oracle.py)是测试侧参考实现，任务 CLI 不导入它。固定计划与正确报告绑定不能防止共同语义错误，必须以“开发通过、参考评价失败”的反例分别验证。本轮全图依赖仍不完备，新增任务检查不会使旧证据自动变为 current。
