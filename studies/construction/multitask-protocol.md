# Bounded multitask and two-stage engineering protocol

Protocol identity: construction-multitask/0.1. This is one fixed small engineering batch, established before development input assembly. Its exit is reusable execution, correctly bound independent evaluation, real state succession, and truthful support/failure boundaries. Stop after this batch; do not add graphs until an advantage appears. There is no LLM, human comparison or demonstrated metamodel-organization advantage.

## Fixed semantics and hierarchy

The evaluator-owned [semantics table](../../tests/fixtures/construction/multitask/semantics.json) fixes four nodes, every initial edge, positive/negative reachability goals, edited identity, ordered endpoint space, option budget and independent outcomes. DAG legality is required for every case. The three core task structures are fork, diamond and disconnected components. The cycle case is an unsupported initial state, not an invitation to repair outside the supported contract. Each model contains one flat graph; no multi-graph support is claimed.

| Stage/case | Budget | Expected first selected redirect / stop |
|---|---:|---|
| fork-stage1 | 4 | edge-cd = b→d at option 4; commit revision 1 |
| diamond | 3 | edge-bd = d→b at option 3; commit revision 1 |
| disconnected | 4 | exhausted; no save; restricted-space failure is not representation_gap |
| fork-stage2 | 4 | edge-ac = d→c at option 4; commit revision 2 |
| unsupported-cycle | 1 | reject cyclic base; record actual exception code and unavailable trace |

Each stage/case runs under terminal-only, dag-construction and ordinary-rule, exactly 15 planned entries. Fork stage 1 is used once per condition: its same run is the first stage of that condition's trajectory, not an additional independent task. Stage 2 enters through that condition's actual BoundedTaskRun and accepted snapshot. A non-commit leaves its descendant planned/not_started with the predecessor reason. Independent-reference failure is recorded separately from commit and does not change the next stage's predeclared task or app behavior.

Every stage-1 statement, obligation and binding remains in stage 2 unchanged. The only added goal is d→c reachable, from a preauthored source. The stage-2 task and space templates use the original parent base on disk; A's advance_construction validates provenance and binds them to the actual accepted snapshot. No candidate is used to author goal truth.

## Conditions and evaluation

All conditions see the same task/model/metamodel/source bytes and edit space, order, budget, builder, terminal checker and save policy. The DAG adapter and ordinary Kahn controller may both parameterize and reuse their rule unchanged. No condition is forced to rewrite equivalent rules for every task. The parent single-task pilot is retained as historical data, not pooled into a sample count.

Reference cases use evaluator-authored fixed reachability expectations and the existing independent test oracle, which also rejects cycles. A fixed reference index binds template bytes before execution. Initial reference task_ref must exactly equal the prepared task_ref before the app is called; a reference for an old task is rejected even if model identity matches. For stage 2 only, load the pinned template, verify its original task_ref against the preauthored stage-2 card, bind task_ref to the runtime prepared reference and set the evaluation version to template.version + '/bound-' + digest(actual_task_ref). Pin the resulting bytes with that distinct version. Store template and bound refs plus the actual bound bytes and binding reason. Model identity, cases and expected values remain unchanged; no candidate authors truth.

The evaluator checks every declared constructed candidate and the saved result once per declared evaluation role. It never feeds results into search, retries the app or substitutes a checker. App saved status, returned result and checker counts remain distinct from reference_status/errors, using the repaired observe_trial implementation. The successor receives the original typed result through a result_sink callback; serialization is not a commit authority.

## Recording, costs and exit

Reuse the single-task recorder and atomic JSON checkpoint writer. Persist the fixed full plan before execution, each started entry, app return before independent evaluation, each terminal/not_started entry and completion. Later errors must retain previously completed entries and any returned app facts. Existing output paths are rejected. No run in runs/ is overwritten. Inputs rejected before app execution preserve their stage/error and unavailable cost values; missing/unknown do not become zero or success.

Report planned/started/terminal/not_started counts, app status and saved counts, per-candidate records, errors and inherited snapshot/task identities. Keep the 15-entry denominator even if a stage cannot start. Input/reference preparation failures have a separate error stage, make the batch error/nonzero, and block only the affected successor; they are not a successfully executed support-boundary probe. This is a nested task/condition/stage matrix, not independent statistical sampling. Out-of-support rejection, restricted-space exhaustion and predeclared budget are separate failure meanings.

Wall time for observe_trial retains the original scope: condition assembly plus full app call and instrumentation, ending before serialization/reference evaluation. Reference time is separate. File input loading, successor binding and reference binding are timed separately as preparation. LLM calls remain zero; human setup and incremental reuse time and machine monetary cost remain null with unmeasured reasons. Source change count cannot stand in for human effort. Same Kahn and DAG algorithms across all tasks demonstrate an engineering reuse boundary, not a causal organization benefit.

Final public collection is owned by A after targeted and full regression and a source freeze. B supplies the runner, fixed references and tests; no final run is claimed here. No task-specific controller branches, production diagnosis, general trajectory engine, rule compiler or backend abstraction is added.
