# 固定任务与保留验收设计

日期：2026-09-23。本文只规定后续研究的输入边界；当前没有生命周期运行器、比较运行或盲测结果。工程参考实现在 `tests/support/task_oracle.py`，公开的参考夹具不属于真正隐藏数据。

## 三类对象的责任

| 对象 | 维护者与内容 | 可见范围 |
|---|---|---|
| TaskContract | 用户或可信任务装配方固定版本化目标、来源、未决声明及开发义务 | 开发过程可见；候选模型变更不能顺便重写任务目标 |
| TaskCard | 研究编排方记录能力轴、进入方式、初始工件、TaskContract 引用、可见信息、资源预算、任务划分和保留验收引用 | 属于研究执行元数据；生产包不读取论文编号或实验条件 |
| HeldOutEvaluationSpec | 评估方固定输入、期望、任务引用、模型/元模型身份、验收版本及来源 | 不送入候选构造、开发检查或修复反馈；候选身份固定后才执行 |

TaskContract 通过生产公共合同被消费，TaskCard 和保留验收对象由研究装配层管理，不能以 `assumptions` 字符串冒充任务身份绑定。开发模型中的可编辑 `trace` 是模型数据，不是保留验收目标。模型保存、固定开发义务满足、参考用例符合及意图忠实分别报告。

## 当前工程参考接口

`pin_evaluation_spec(raw_json, expected_ref)` 接收 UTF-8 字节或文本以及评估方事先固定的 ArtifactRef，核对原始字节 SHA256、结构和身份。期望引用必须由可信评估方在候选出现前选择，不能根据候选同时提交的文件临时计算。JSON 中不提供自报哈希；空白变化也改变制品哈希。检查候选与计划的规范化摘要仍沿用公共协议。

`evaluate_candidate(snapshot, pinned_spec)` 无模型写入，返回 `spec_ref`、`task_ref`、`candidate_ref` 及每条参考用例的 `status/finding`。结果覆盖全部用例，不存在空结果通过。缺失预期真值或不支持的规则为 unknown；结构错误与规则违背分别报告，不能以非法自动机作为负向期望的成功见证。跨项目、模型或元模型版本/内容的候选拒绝求值。

工程参考 JSON 为 `task-evaluation/0.1`，内容包括：

- `id/version/task_ref`：参考规格身份及固定任务制品引用；引用是定位和完整性信息，不能证明来源真实或意图已忠实表达。
- `model`：项目、模型、元模型身份和元模型内容哈希；不声称验证候选的完整版本祖先链。
- `cases`：`id/kind/target/input/destination/expected`。图可达性以 `input/destination` 指定固定端点；有限自动机以 `input` 指定输入串，`destination=null`。`expected` 是布尔值，显式 null 表示未决真值。

参考图算法通过独立广度搜索检查有向无环性与固定端点可达性；有限自动机先验证扁平成员、端点、状态标记、单 Unicode 码点符号及确定性，再逐个输入展开状态集合。超出声明字母表的输入为 unknown，不能满足负向期望。它们不导入生产检查器或适配器语义辅助函数，且不读取开发 CheckPlan。该实现只支持当前有限图和自动机语义，不能解释通用时序逻辑、守卫、数据效果或应用代码行为；未支持字段/成员不被静默忽略。

## 开发可见与保留输入

调用关系是：评估方固定任务/验收引用 → 只向开发方提供 TaskContract 和初始制品 → 固定终态候选身份 → 独立调用参考验收。开发报告不得包含保留用例及其期望；最终评价产生的反馈不重新喂给同一次被评分的候选修复。若研究允许有限反馈或多轮评价，须事先将反馈范围、轮数、预算与最后留出集写进协议。

当前 `tests/fixtures/task-acceptance/` 的输入与期望依据各配置 `tasks/source.txt` 的明确要求固定，不能额外添加源任务未要求的拒绝条件。参考用例可以与开发义务对应，代码作者也可以看见它们；这不是未见任务集或盲测。当前调用边界只承诺不把评估规格作为参数传入开发调用，不能防御拥有整个文件系统权限的代理。真实研究需由执行边界隔离保留材料，并记录各方法实际读取了哪些信息。

## 任务卡的后续内容与启动条件

后续每张任务卡至少填写：方法无关的目标、表达/行为/演化/入口覆盖、TaskContract 精确引用、初始制品、可见开发资料、保留规格引用及审定依据、预算与停止规则、纳入/排除原因、开发/试运行/最终评价划分。未决意图和无法确定真值的部分单列，不通过删去任务或缩小分母制造成功。

先做固定任务的工程正反验收，再在对应生产机制及可比对照可运行后启动局部研究；不要求等待全部模块或论文完成。真实比较须另外设计独立真值审定、来源依赖关系、相关错误、等预算对照和成本记录。不同文件、工具名称或实现算法不自动构成统计独立；本轮只提供由同一研究团队分别构造的参考工程依据，不支持 P2/H2 或总体优势结论。

既有业务夹具和这两类有限模型都不指定后续应用方向。TaskCard 只据研究问题选任务，不将可运行夹具自动转为首期产品或完整实验集。
