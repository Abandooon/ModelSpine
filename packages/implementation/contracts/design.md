# 实现与交付目标合同

状态：draft，2026-09-21；运行模块仍 planned。此前 [v0.1](v0.1/README.md) 的业务数值/角色只是工程样例，不是通用合同默认值。

输入：版本化模型、候选制品、业务操作定义、目标技术栈、外部能力/采用计划、文件所有权及交付策略。拥有 CommandBinding、文件计划、MigrationPlan、ApplicationBuild。依赖 protocols/generation；为 interaction 供应公开命令合同，不要求后者导入构建器。

## 操作合同

| 操作 | 输出 | 副作用 |
|---|---|---|
| bind | CommandBinding | 只定义绑定，不执行业务命令 |
| materialize | 文件结果、冲突、来源映射 | 只写声明且获授权的目标范围；部分失败必须报告已写/未写/恢复状态 |
| build | 构建制品、命令/工具版本、报告、残余 | 在声明环境执行；失败不能返回成功制品 |
| package | 交付制品或拒绝 | 按固定策略核对终验，不隐含发布/部署 |
| migration-plan | 结构/数据变更、顺序、前提、恢复限制 | 计划不等于迁移执行；应用数据不由 kernel 直接写入 |

CommandBinding 必含 id/version、operation_ref、model/contract refs、输入/输出类型、权限、前后条件、状态效果、错误、并发及重试语义。应用 runtime_instance_version 与设计 revision 分开；数值类型、单位、精度和表示由配置声明。无变化请求是否改变版本由该操作合同规定，不设全平台业务默认。

## 文件与执行边界

FilePlan 包含目标根、相对路径、owner(generated/human/third_party)、expected_old_hash/new_hash、来源与允许操作。拒绝路径越界、非预期旧内容和未经声明的覆盖；新文件要求目标不存在。首期可整文件管理，不预做任意代码区域合并。

模型保存、文件物化、构建、数据迁移和交付是不同提交点。目标合同必须列出真实原子范围及失败恢复办法；不能承诺未实现的全局事务。执行身份由宿主认证提供，前端显示按钮不授予权限。

## 设计验收

A：命令类型与服务实现一致，缺必需终验不交付。B：旧应用版本/文件哈希冲突，失败不覆盖人工内容；模型已保存但构建失败如实保留。C：采用组件只写适配范围，组件版本不符/能力未知保留诊断。程序运行合同需实际后端测试，结构化样例通过不等于运行正确。
