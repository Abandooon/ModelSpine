# 生成与修复目标合同

状态：draft，2026-09-21；[v0.1](v0.1/README.md) 仅单字段候选控制与纯报告比较。候选生成、文件物化和最终交付为不同责任。

输入：版本化元模型/模型、已知任务目标、assurance 义务/支持说明、生成目标和预算。拥有 GenerationPlan、CandidateArtifact、RepairProposal、运行轨迹；输出给 implementation 或编排，由 kernel 接受模型提案。依赖 protocols/assurance，不直接改已接受模型或应用文件。

## 公开操作设计

| 操作 | 输入 → 输出 | 边界 |
|---|---|---|
| plan | 目标、模型、义务、后端能力、预算 → GenerationPlan | 每义务列控制阶段、机制、支持片段和残余终验 |
| generate | 固定计划与输入 → CandidateArtifact、控制记录、RunReceipt | 候选绑定原始响应/构造后结果；失败保留原响应，不能补默认成功 |
| repair | 候选、报告、允许修改范围、预算 → RepairProposal/轨迹 | 不改真值、检查器或来源类别；达到预算停止 |
| compare_reports | 可比较前后报告 → 改善/回归/覆盖损失/不可比较 | 改善不是模型提交或交付许可 |

GenerationPlan 明确 generator/rule/interface/model 版本、每义务 intervention_stage、controller_ref、残余检查、尝试/时间/费用上限。CandidateArtifact 包含输入、内容哈希、目标格式、追踪、未满足义务及所有权建议；所有权最终由 implementation 审核。

生成控制至少区分合法模型操作、构造空间限制、生成中选择、后验检查。实际执行日志才能支持阶段干预声明。提示中出现规则或导出公式不自动算硬约束；同一义务即使被前置控制仍可保留独立终验。

## 修复、失败与成本

基准义务集合与语义版本在一次修复比较中固定；若需求本身变化，开启新的任务基准，不以删义务降低错误数。新增诊断、已评估义务丢失或未知化不得悄悄接受。是否允许显式豁免属于将来合同变更，不继承旧来源全部分支。

停止包括成功、无进展、无可修复项、重复候选、预算耗尽、取消和执行错误；次数/时间/费用仅记录实际获得的值。失败不自动换模型或验证器。支持范围不足时返回残余，不能无限修复直到偶然通过。

## 设计验收

A：同一约束在构造阶段排除非法候选，绕过构造的反例仍被终验拒绝。B：修复改善但尚有违反只标进展；不同规则/范围报告拒绝直接比较。C：外部组件缺口成为明确残余，不把接口相似当满足。对照共享输入与工具，控制阶段分别消融，具体研究见 P2/E。
